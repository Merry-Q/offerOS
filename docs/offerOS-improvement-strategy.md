# OfferOS 改进策略

> 版本：v1.2｜2026-07-28  
> 状态：产品策略稿；**Phase 1–4 产品能力已落地代码**（SSE/队列/模型路由等基建项仍属后续）  
> 相关文档：`docs/speed-optimization-plan.md`（P0/P1 已落地）、`docs/batch-match-interaction.md`（批量交互探索稿）  
> v1.1：补充批量「网页链接抽岗」、匹配库「公司/岗位/地区」筛选与投递跳转链接  
> v1.2：策略对应能力已实现（批量匹配、链接抽岗、自动选简历、偏好、证据池、投递状态、公司视图、故事库）

---

## 1. 核心目标

把 OfferOS 从「单岗匹配报告机」升级为：

> **懂用户的专属求职顾问**——帮用户更快完成匹配决策与面试准备，并以跨岗位投递策略支持转岗行动。

### 1.1 目标拆解

| 目标 | 含义 | 可感知结果 |
|------|------|------------|
| 懂用户 | 理解方向、约束、多简历策略与历史决策 | 越用越少重复解释；推荐用哪份简历投哪个岗 |
| 匹配决策效率 | 先筛后深，单位时间可决策岗数上升 | 晚间可完成「多评少深」（如 8 评 2 深） |
| 备面效率 | 高意向岗有针对性打法，而非泛泛模拟 | 按缺口出改写与面试包，可跨简历取材 |
| 跨岗位 / 转岗 | 多方向简历与证据池开放复用 | 转岗时知道用哪版简历、哪些故事可迁移 |
| 差异化 | 相对 Boss 等平台成为「投递前决策层」 | 用户心智：「岗在平台看，投前先过 OfferOS」 |

### 1.2 非目标（近端明确不做）

- 自建岗位大盘或替代 Boss / 拉勾等招聘入口  
- **全站爬岗 / 主动发现岗位**（仅处理用户主动提交的网页链接或粘贴/截图）  
- 以「AI 代投更多」作为主价值（平台已在做，且激励冲突）  
- 为提速牺牲报告质量（Action 质量契约保持）  
- 一上来做完整职业规划表单或重型 CRM

## 3. 定位与差异化

### 3.1 品类定位

| | 大型招聘平台（如 Boss 直聘） | OfferOS |
|--|------------------------------|---------|
| 本质 | 双边撮合市场 | 单边决策与行动引擎 |
| 供给 | 岗位库存 + 直聊 | 用户自带任意来源 JD |
| 成功定义 | 开聊 / 达成 / 平台闭环 | 正确决定投不投 + 改得动、面得赢 |
| 激励 | 更多互动与投递 | 少而准的投；敢说「不建议投」 |
| 在链路中的位置 | 找岗与沟通主场 | **投递前的顾问层**（上游决策） |

**对外一句话：**

> OfferOS 是投递前的专属求职顾问：把任意来源的 JD（粘贴、截图或**岗位网页链接**），变成「该用哪份简历、该不该投、差在哪、怎么改、怎么面」——支持一次多岗筛选，匹配库可按公司/岗位/地区找回并**一键跳回原页投递**，并开放跨岗位经历复用，帮你把好转岗与多方向投递。

**用户心智检验：**

> 「岗还是在 Boss 上看；**投之前一定先丢进 OfferOS。**」

### 3.2 相对 Boss 等平台的差异化支柱

| 支柱 | 内容 | 平台难跟原因 |
|------|------|--------------|
| 独立顾问立场 | 保/稳/冲/**不建议投** + 致命缺口 | 平台激励偏向多互动，难认真劝退 |
| 可解释匹配 | 三维加权分 + 要求匹配表 + 证据/缺口 | 推荐偏黑盒；润色偏语言美化 |
| 跨平台工作台 | JD 来自 Boss/官网/内推均可；**链接导入 + 保留投递跳转** | 平台资产锁在站内；难服务「站外再决策再跳回投」 |
| 多简历策略 | JD 自动匹配最合适简历；跨岗证据池 | 通常一份在线简历 |
| 先筛后深 | 批量判分榜 → 按需高质量报告 | 平台优化的是推荐流，不是「今晚 8 评 2 深」 |

### 3.3 明确不碰的战场

- 岗位搜索与推荐大盘  
- 站内开聊 / 代聊主链路  
- 纯情绪陪伴型对话助手  
- 单点「简历润色」红海功能（除非绑在本岗缺口与证据链上）

## 4. 策略框架

### 4.1 四个能力支柱

```
① 懂你              ② 筛岗                    ③ 决策              ④ 行动
画像 + 薄偏好        批量匹配榜                保稳冲 + 结论       改简历 + 面试包
多简历标签           粘贴/OCR/网页链接抽岗     不建议投            跨岗证据取材
                     JD→自动选简历                                   一键跳转投递链接
      ↑______ 匹配库（公司/岗位/地区筛选 + 源链接）/ 证据池 / 投递推进 ______↑
```

### 4.2 近端北极星与辅助指标

**近 1–2 个迭代北极星（吞吐型）：**

> **单位时间可决策岗数** —— 例：30 分钟内完成「8 评 2 深」。

**辅助指标：**

| 指标 | 作用 |
|------|------|
| Time-to-Decision | 点击判分 → 看到档位/分数 |
| 建议简历采纳率 | JD→自动选简历是否可信 |
| 星标/高分岗报告打开率 | 筛完是否进入深耕 |
| 跨简历取材使用率 | 转岗/多方向是否被用起来 |
| 链接导入成功率 / 抽岗可编辑率 | 网页抽岗是否可用 |
| 匹配库筛选用次 / 投递链接点击率 | 回跳平台投递是否顺畅 |
| 「不建议投」后的行为 | 是否减少无效投递（抽样质检） |

**翻盘条件：** 批量上线后，若「有榜但很少生成报告 / 很少推进投递」占比高 → 将北极星切到「高意向岗推进完成率」，并提前投递状态机。

### 4.3 场景优先级

| 优先级 | 场景 | 策略含义 |
|--------|------|----------|
| P0 | 今晚 Boss 海刷多段 JD / 多条岗位链接 | 扁平批次榜；支持链接抽岗；公司名为选填 |
| P0 | 多方向 / 转岗：不知用哪份简历 | JD 自动推荐主简历 |
| P0 | 评完要回去投 | 匹配库保留投递链接；按公司/岗位/地区筛 |
| P1 | 高意向岗改简历 + 备面 | 深报告 + 跨简历证据池 |
| P2 | 盯一家目标公司多岗 | 公司聚合（用数据触发再做） |

### 4.4 关键原则

1. **质量用架构保住，效率用节奏优化** —— 深报告标准不降；批量默认只判分。  
2. **主路径只阻塞决策** —— 先出该不该投，再按需深耕。  
3. **推荐默认、人可改** —— 自动选简历是建议，不是黑盒替身。  
4. **开放取材、禁止编造** —— 跨简历可引用，须标注来源；不造假经历。  
5. **与招聘平台互补** —— 文案与导入默认假设「JD 来自 Boss 等渠道」；**决策在 OfferOS，投递跳回源链接**。  
6. **元数据跟 JD 走** —— 公司、岗位名、地区、投递链接随导入沉淀到匹配库，支撑筛选与回跳。

## 5. 优化行动（What）

### 5.1 行动包 A：批量匹配（筛选入口）

**目标：** 把效率瓶颈从「写报告」挪回「筛选」。

**关键动作：**

- 入口：批量匹配与单岗匹配并列；单岗保留为深耕入口  
- 输入（组合支持）：  
  - 批量粘贴 JD 文本  
  - 多图 OCR  
  - **网页链接**：用户粘贴一条或多条岗位页 URL，系统抓取页面并自动提取岗位信息（标题、公司、地区、JD 正文等），回填为可编辑岗位卡片  
- 岗位预览可删改；链接导入须保留 **source_url（投递/原岗位链接）**  
- 执行：默认只跑 JD 解析 + Judge；深报告按需或星标触发  
- 输出：匹配榜（分数/档位/一句话/致命缺口/状态）；禁止榜上展开完整六模块  
- 首期：扁平批次；公司名/地区优先从页面抽取，可手改；不做重型公司实体  
- 上限：单批 10–20 岗；hash 去重（含 URL 规范化去重）；失败行可单独重试  

**网页链接抽岗规格（产品要求）：**

| 项 | 要求 |
|----|------|
| 输入 | 单条或批量 URL（换行分隔）；可与粘贴/OCR 混用同一批次 |
| 系统行为 | 拉取页面 → 抽取岗位结构化字段 + JD 文本 → 生成预览卡 |
| 抽取字段 | 岗位标题、公司名、地区/城市、薪资（若有）、JD 正文；**必留 source_url** |
| 失败降级 | 登录墙 / 反爬 / 非岗位页 → 标记失败，引导改粘贴或截图，不阻塞整批 |
| 用户确认 | 抽取结果一律可编辑后再「开始判分」；不默认静默开跑 |
| 边界 | 不做全站爬岗；只处理用户主动提交的链接（导入-only，非供给市场） |

**待决拍板（建议默认）：**

| 议题 | 建议 |
|------|------|
| 批量结束后自动 Top-K 深报告 | **默认关**；星标/手动开 |
| 公司层 | **首期不做实体**；公司名作筛选字段即可 |
| OCR / 链接抽岗失败 | 转手动粘贴或截图，不占死坑 |
| 移动端粘贴板第一入口 | 桌面先做，移动后置 |
| 优先适配站点 | 先通用抽取；对 Boss/常见招聘页做体验优先验证 |

**成功标准：** 30 分钟内「8 评 2 深」，且 2 份深报告质量与单岗一致；链接导入岗位可编辑率高、失败有明确降级。

**依赖：** 提速解耦已满足（见 `speed-optimization-plan.md`）。交互细节见 `batch-match-interaction.md`（需增补「链接导入」步骤）。

### 5.2 行动包 A2：匹配库筛选与投递跳转

**目标：** 决策结果可回找、可筛选，并一键回到原平台投递——闭合「平台找岗 → OfferOS 决策 → 平台投递」。

**关键动作：**

- 匹配库（及批量结果沉淀后的列表）支持筛选：  
  - **公司**（精确/模糊）  
  - **岗位**（标题关键词 / 解析出的 title）  
  - **地区**（城市或「远程」等；无则显示「未知」可筛）  
- 每条岗位保留并展示 **投递链接（source_url）**；提供「打开原岗位 / 去投递」跳转  
- 单岗粘贴若无链接：允许用户补填投递 URL；链接导入则自动写入  
- 列表行信息：公司 · 岗位 · 地区 · 档位/分数 · 报告状态 · **投递链接入口**  
- 与行动包 E 衔接后：筛选可叠加投递状态（待投/已投等）

**数据字段（岗位/匹配侧最小集）：**

| 字段 | 来源 | 用途 |
|------|------|------|
| company | 链接抽取 / 用户填写 / JD 解析猜测 | 公司筛选与展示 |
| title / role | 同上 | 岗位筛选与展示 |
| location | 同上 | 地区筛选 |
| source_url | 链接导入必填；手填可选 | 跳转投递 |
| 判分与报告状态 | 现有 match_run | 决策回看 |

**成功标准：** 用户能按公司/岗位/地区快速定位历史匹配，并从 OfferOS **一键跳回**原岗位页投递。

**说明：** 这不是自建岗位市场；链接由用户导入或补录，OfferOS 只做存储、筛选与回跳。

### 5.3 行动包 B：JD → 自动匹配最合适简历

**目标：** 多简历从「仓库」变成「策略」；降低转岗/多方向时的选择成本。

**关键动作：**

- JD 确认后，对库内已解析简历给出 **推荐主简历 + 理由 + 备选**  
- 默认「用建议简历继续」，保留「我自己选」  
- 批量：每行可显示所用简历；支持「本批按岗自动选」  
- 实现路径：  
  - v1：简历数少时对每份轻量/完整 Judge 取 Top1  
  - v1.5：profile × must_haves 粗排 → Top2 精跑；复用 `resume_id + jd_hash` 缓存  

**成功标准：** 建议采纳率可观测且 >50%；手选纠错后分数显著更高的比例作为质检。

---

### 5.4 行动包 C：懂用户（薄偏好 + 简历策略标签）

**目标：** 冷启动「顾问感」，不做成表单地狱。

**关键动作（最小集）：**

- 目标方向 / 职级意向 / 城市或远程 / 1 条硬约束（可选）  
- 简历可选方向标签（如：产品执行 / 策略 / 数据）  
- 影响：榜筛选、one_liner 语境、自动选简历粗排  
- **不阻塞**「开始判分」；不重训为唯一分数来源  

偏好表已有 DB 残留，优先产品化最小字段，避免平行造轮子。

---

### 5.5 行动包 D：跨岗位改写与备面（证据池开放）

**目标：** 增强转岗与多方向投递的可执行性。

**模型拆分：**

| 概念 | 定义 |
|------|------|
| 主简历 | 自动匹配或用户选定的投递载体；判分与默认改写对象 |
| 证据池 | 库内全部简历画像/经历的可验证事实集合 |

**关键动作：**

- 深报告设置：「允许跨简历取材」（**默认开**）/「仅用当前简历」  
- 改写与面试包可引用其他简历经历，**标注来源**（如「来自：策略向 v2」）  
- 缺口题优先从证据池捞可讲故事；主简历缺失时提示「建议写回主简历」  
- 后续：一键将迁移故事写回主简历新版本（版本冲突需设计）  

**硬约束：** 跨简历 ≠ 伪造；只能重组已有事实，延续 Action「禁止编造」契约。

---

### 5.6 行动包 E：决策后推进（投递轻状态）

**目标：** 避免「筛完就走」；服务转岗行动的后半段。

**关键动作（跟在批量验证后）：**

- 匹配行/详情增加轻状态：待改简历 → 待投 → 已投 → 面试中 → 结束  
- 高意向（星标/稳冲）默认进入「待改简历」；有 source_url 时可从「待投」一键打开原岗  
- 不做重型 CRM；先 4～5 态 + 列表筛选（与 A2 的公司/岗位/地区筛选叠加）  

**触发提前条件：** 批量上线后深报告打开率低或用户反馈「评完仍不知道下一步」。

---

### 5.7 行动包 F：公司层（数据触发）

**目标：** 回答「这家公司我该攻哪个岗」。

**关键动作：**

- 当同一公司名在用户数据中反复出现（如 ≥3）再升级公司卡  
- 聚合：该公司多岗分数、常见 must_have、相对强弱  
- **不作为海刷主路径的阻塞项**

## 6. 排期（When）

### 6.1 总览

```
Phase 0 已完成     提速：判分/报告解耦、缓存、模块编排
        │
Phase 1  Now       批量匹配 v1（含链接抽岗）+ 匹配库筛选/投递链接 + 自动选简历
        │
Phase 2  Next      薄偏好/简历标签 + 跨简历证据池（深报告）
        │
Phase 3  Then      投递轻状态 + 写回主简历 +（数据触发）公司层
        │
Phase 4  Later     故事库产品化、移动粘贴板优先、站点适配增强、模型路由等
```

### 6.2 分阶段明细

#### Phase 1 — 筛选吞吐、回跳投递与多简历策略入口（约 1～1.5 个迭代）

| 序号 | 事项 | 包 | 产出 |
|------|------|----|------|
| 1.1 | 批量匹配 PRD 定稿（含链接抽岗；自动深报告默认关） | A | 可开发 PRD |
| 1.2 | 批量输入（粘贴/OCR/**网页链接抽岗**）+ 只判分 + 匹配榜 | A | 可用海刷路径 |
| 1.3 | 岗位元数据落库：公司 / 岗位 / 地区 / source_url | A/A2 | 可筛可跳 |
| 1.4 | 匹配库：按公司、岗位、地区筛选 +「打开原岗位/去投递」 | A2 | 决策→回跳投递 |
| 1.5 | 榜上行：星标 / 生成深报告 / 打开详情 / 投递链接 | A/A2 | 先筛后深+可投 |
| 1.6 | JD → 推荐主简历 + 理由 + 可手选 | B | 单岗 + 批量均可挂 |
| 1.7 | 埋点：批次规模、链接成功率、TTD、筛选使用、链接点击、采纳率 | A/A2/B | 北极星可测 |

**阶段成功：** 用户可「贴链接或 JD → 批量判分 → 库内按公司/岗位/地区找回 → 一键跳回原页投递」；转岗用户减少选错简历。

#### Phase 2 — 懂你 + 跨岗行动力（约 1 个迭代）

| 序号 | 事项 | 包 | 产出 |
|------|------|----|------|
| 2.1 | 薄偏好最小集 + 简历方向标签 | C | 顾问冷启动 |
| 2.2 | 证据池：跨简历取材开关（默认开） | D | 改写/面试可引用 |
| 2.3 | 来源标注 + 写回主简历提示 | D | 转岗可执行感 |
| 2.4 | 自动选简历粗排优化（控 Judge 成本） | B | 批量×多简历可扩展 |

**阶段成功：** 多方向用户能感到「系统知道我有多版简历，且备面能借到另一方向的故事」。

#### Phase 3 — 推进闭环与公司视角（约 1 个迭代，可按数据裁剪）

| 序号 | 事项 | 包 | 产出 |
|------|------|----|------|
| 3.1 | 投递轻状态机 + 列表筛选 | E | 决策→行动 |
| 3.2 | 迁移故事写回主简历（版本） | D | 资产沉淀 |
| 3.3 | 公司名聚合视图（触发式） | F | 「攻哪条业务线」 |

**阶段成功：** 高意向岗从「有报告」到「有下一步状态」；盯公司用户能横向比较。

#### Phase 4 — 增强与平台化（视资源）

- 跨岗故事库独立浏览与检索  
- 移动端粘贴板快速追加为第一入口  
- 常见招聘站链接抽岗适配增强（反爬/结构变更应对）

- 模型路由（抽取快 / 报告强）  
- 质量抽检清单常态化（提速文档 §10）

## 7. 风险与缓解

| 风险 | 缓解 |
|------|------|
| 批量 × 多简历导致 LLM 成本暴涨 | 默认只判分；自动选先粗排；强缓存；单批上限 |
| 网页链接抽岗失败（登录墙/反爬/SPA） | 失败降级粘贴/OCR；预览可编辑；优先验证高频站点 |
| 投递链接失效或需登录 | UI 标明「原岗位链接」；失效时引导用户更新 URL |
| 用户误解「跨简历取材」为假简历 | 来源标注 + 设置开关 + 文案强调禁止编造 |
| 自动选简历不准伤害信任 | 建议态非强制；展示理由；采纳率与纠错率监控 |
| 与 Boss AI 助手话术撞车 | 对外强调独立顾问、透明分、跨平台、敢不建议投 |
| 范围膨胀（做成小 Boss） | 非目标清单季度复习；**只处理用户提交的链接，不做全站爬岗** |
| 异步任务单进程不稳 | 批量上线前评估队列；状态机以 DB 为准可恢复 |

## 9. 策略摘要（一页纸）

```
定位：投递前的专属求职顾问（平台上游决策层），非小型招聘市场
差异：独立立场 · 可解释匹配 · 跨平台 JD（链接导入）· 多简历策略 · 先筛后深
北极星（近端）：单位时间可决策岗数（如 8 评 2 深）
主路径：链接/粘贴批量判分 → 自动选主简历 → 按需深报告 → 跨岗取材改/面
回跳：匹配库按公司/岗位/地区筛选，一键打开投递源链接
转岗：多简历推荐 + 证据池开放 +（随后）写回与轻投递状态
排期：批量+链接抽岗+匹配库筛选 → 薄偏好+证据池 → 投递状态+公司触发 → 增强项
底线：不砍报告质量；不抢岗位供给；只导入用户链接；推荐可改；取材不编造
```
