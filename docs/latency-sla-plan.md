# 延迟 SLA 提速方案（质量不降级）

## 需求确认

| 环节 | 目标 | 质量底线 |
|---|---|---|
| JD 解析 | **3–5 秒** | 结构化字段完整，不编造门槛 |
| 综合判分 | **≤ 10 秒** | 三维分 + 档位 + 缺口可信，不编造证据 |
| 行动方案 | **≤ 60 秒** | 六模块结构保留；must_haves 覆盖；可执行改写/面试 |

原则：**用模型分层、输入压缩、并行与输出上限提速；不砍模块、不取消覆盖校验。**

## 行动项

1. **模型路由**
   - `GLM_FAST_MODEL`（默认 `glm-4.7-flash`）→ JD / Judge
   - `GLM_ACTION_MODEL`（默认 `glm-5.2`，可改为更快 Air）→ Action 四模块
2. **请求侧**
   - 关闭 thinking（避免推理拖慢）
   - 按任务设置 `max_tokens` 与更短 timeout
3. **输入压缩**
   - JD 文本截断至 ~5k；Judge 只传精简画像字段
4. **Action 编排**
   - M1–M4 **一轮四并行**（M3/M4 直接用 judge.gaps，不再串第二波）
   - 字数上限略收紧，结构与覆盖校验保留
5. **缓存**（已有）继续生效，复跑同 JD/同匹配对接近瞬时

## 验收

- 冷启动（无缓存）：JD ≤5s，Judge ≤10s，Report ≤60s（网络正常）
- 有缓存：应远低于上述
- 抽检报告：must_haves 覆盖、改写/面试仍可执行
