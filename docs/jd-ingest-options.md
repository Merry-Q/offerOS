# 岗位信息获取方式（网页链接）备选方案

> 状态：待产品确认｜2026-07-28  
> 背景：服务端抓取 Boss/拉勾等招聘页准确率低（反爬、登录墙、SPA），不宜继续作为主路径硬撑。

## 建议结论

**推荐：链接降级为「投递入口」；岗位正文改由截图/粘贴提供（方案 A 为主，B 为增强）。**

理由：OfferOS 的核心是决策与行动，不是岗位供给；抓取正确率受平台控制，投入产出差。

---

## 方案对比

| 方案 | 用户怎么做 | 准确率预期 | 开发量 | 风险 |
|------|------------|------------|--------|------|
| **A. 链接只作投递跳转** | 粘贴/截图提供 JD；可选填原链接用于「去投递」 | 高（跟人眼输入一致） | 低：弱化/隐藏自动抓取 | 多一步粘贴 |
| **B. 半自动「打开页 → 复制正文」** | 点链接用浏览器打开；一键从剪贴板追加 JD | 高 | 低–中 | 仍依赖用户复制 |
| **C. 浏览器扩展抽取** | 在岗位页点扩展「送入 OfferOS」 | 高 | 高 | 分发/审核/维护 |
| **D. 继续服务端抓取 + Reader** | 贴 URL 自动抽 | 低–中（Boss 等常失败） | 已做过一轮仍不稳 | 反爬持续升级 |
| **E. Playwright 无头浏览器** | 贴 URL | 中（仍可能登录墙） | 高，运维重 | 不稳定、占资源 |

## 推荐落地（若选 A+B）

1. **批量匹配默认入口**：粘贴 JD / 截图；网页链接改为「保存投递地址」，不再承诺自动抽全文。  
2. **单岗**：保留「原岗位链接」字段；截图识别修好后作为主获取方式。  
3. **可选增强**：按钮「从剪贴板导入 JD」+「打开链接」并排。  
4. **现有 extract-jd-url**：保留为高级/实验，或标注「成功率低，失败请改粘贴」。
