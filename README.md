# OfferOS

个人求职匹配引擎（FastAPI + SQLite）。

主链路：**简历 → 本地分模块档案与原文证据 → 匹配岗位（联网发现、详情核验、快速排序） → 点击生成岗位长报告**。也支持直接粘贴公开 JD 或招聘链接。公开站点默认进入虚构人物 Demo，无需登录注册。

## 本地开发

```powershell
cd offerOS
python -m pip install -r requirements.txt
copy .env.example .env
# 编辑 .env：填入 DASHSCOPE_API_KEY（可选）；务必修改 ADMIN_PASSWORD
python -m uvicorn server.main:app --reload
```

启动后访问 `http://127.0.0.1:8000/`。打开首页会自动进入虚构人物 Demo，无需登录。

默认管理员由 `.env` 自动初始化（`ADMIN_USERNAME` / `ADMIN_PASSWORD`）。若仍使用环境默认口令，登录后会提示改密。

公开 Demo 由启动时自动写入：虚构人物「林知夏」、四份岗位分析（保 / 冲 / 稳 / 不建议投）。运行 `python scripts/seed_demo.py` 可重置这些演示数据。
若库中尚无管理员，可在 `/admin/register` 创建首位管理员（仅一次）。

## 环境变量（`.env`）

| 变量 | 说明 |
|------|------|
| `DASHSCOPE_API_KEY` | 大模型 Key（**仅后端**） |
| `DASHSCOPE_BASE_URL` | 百炼兼容接口，默认中国内地 `dashscope.aliyuncs.com/compatible-mode/v1` |
| `DASHSCOPE_GENERATION_URL` | 百炼原生联网搜索接口；新版工作空间按控制台配置地域与空间端点 |
| `QWEN_MODEL` / `QWEN_ACTION_MODEL` | 主模型与报告模型，默认 `qwen-plus` |
| `QWEN_FAST_MODEL` / `QWEN_SEARCH_MODEL` | JD/判分默认 `qwen-flash`；联网搜索默认 `qwen-plus` |
| `DISCOVERY_LIMIT` | 一次最多显示的核验结果，默认24，范围3–60 |
| `DISCOVERY_SEARCH_ROUNDS` | 不足目标时补搜的路数，默认6，范围1–6，同时最多2路 |
| `DISCOVERY_CANDIDATE_LIMIT` | 搜索引用与一跳详情共用的核验预算，默认96，上限160，不低于结果上限 |
| `DISCOVERY_VERIFY_WORKERS` | 页面核验并发，默认4，范围1–6 |
| `LLM_MODE` | `auto` / `mock`；mock不进行联网发现，不生成伪造岗位 |
| `ADMIN_USERNAME` / `ADMIN_PASSWORD` | 启动时若不存在则创建管理员；请用强密码 |
| `ENVIRONMENT` | `development` / `production`（production 默认关 docs） |
| `DISABLE_DOCS` | `true` / `false`，覆盖文档开关 |
| `CORS_ORIGINS` | 逗号分隔来源；同域可用 `*` |
| `MAX_UPLOAD_MB` | 上传上限（MB），默认 `5` |

**切勿**将 `.env` 或 `data/` 提交到 Git。

## 产品能力

系统虚构示例已补齐9个模块、49条原文事实，包括求职期望、教育、工作、实习、3个项目、技能、证书奖项与作品集说明；与上传档案采用相同的证据校验。点击分析会立即进入结果区，等待过程中原位显示进展；岗位导入区可通过按钮展开、收起。后端职责、模型编排和隐私边界见[后端设计说明](docs/backend-design-and-analysis-flow-2026-10-23.md)。

1. **简历档案**：上传 PDF / Word / Markdown / TXT，按基本信息、教育、工作、实习、项目、技能等模块归档；每条信息保留原文引用和提取文本行号，支持多简历切换与完整原文查看。仅依据当前简历，未写出的能力按未具备处理，不支持追加简历外经历。首次上传自动切换到独立访客身份，避免写入共享 Demo。
2. **面试练习**：依据当前简历经历生成练习问题，支持文本回答、浏览器实时语音转写和面试复盘报告。
3. **匹配岗位**：百炼原生联网搜索返回来源引用，仅核验真实来源页及其一跳详情链接。通过公司、职位、完整JD与在招依据检查后，本地快速评分并降序排列；未注明城市/类型/届次保持未知。点击岗位重新核验并生成长报告。
4. **岗位输入与隐私**：支持公开链接与文本；简历解析、本地证据绑定和面试复盘不调用模型。上传图片的云端OCR已关闭。姓名、联系方式、学校、前雇主、项目名称、原文与精确日期不发送给模型，仅发送固定职业标签。报告不再向模型传递跨简历证据。
5. **岗位证据**：提取公司、地点、招聘类型、专业/学历/经验/语言硬门槛、加分项与核心能力。
6. **公司背景**：百炼联网检索公司主营业务、行业位置、近半年动态和公开融资/经营情况，整合为一项公司背景；每条结论引用实际搜索来源，区分事实与分析。两个岗位分析入口都会发起背调并保存到历史记录，失败时可重新背调。
7. **四维匹配**：35% 知识技能 + 25% 工作经验 + 25% 核心能力 + 15% 个性特质；硬门槛只警示，不篡改原分和保稳冲档位。
8. **面试准备**：报告删除简历修改建议，分为简历侧经历深挖和职位侧业务/专业知识。简历侧在本地根据原文项目生成问题与证据行号；职位侧使用qwen-flash根据公开JD生成回答要点、知识点、追问和易错点，输出不足时以明确标注的本地提纲补齐。不补造候选人经历，不将原文发送给模型。
9. **历史分析与管理端**：保留完整分析结果；管理端提供漏斗、质量和用量指标。
10. **账户与 Demo**：公开站点自动进入虚构演示账号，无需注册登录；管理端仍需管理员账号。

## 匹配岗位的边界与验证

这是按需发现流程，不维护自建岗位库存。默认目标24个结果：招聘平台、企业招聘系统、技能方向、公司官网、更多平台、公开招聘补搜最多6路，两路同时搜索，每路接收最多24个真实引用。未达到目标时，从最多12个来源页提取实际同站职位链接或JobPosting网址，每页最多8条、每轮最多24条；搜索引用与详情合计最多核验96个候选页面，并发数4。达到目标或预算后停止补搜。跟踪参数、重复网址和相同公司/职位/城市/原文的镜像结果会合并。

部分搜索失败不会丢弃其他来源结果。搜索过程会保存并展示已核验岗位及检查数量，结束后开放分析按钮；一次搜索通常比原先耗时更长、模型调用更多。旧`.env`若显式设置`DISCOVERY_LIMIT=6`，需改为24并重启服务。搜索引用本身不代表职位在招。每次进入长报告前重新抓取详情；登录、验证码、脚本空壳、过期或关闭岗位会被排除。可见申请入口只代表核验时页面有申请入口，不保证HR持续招聘。

同一用户的同一简历，每次搜索新增一页，旧页不覆盖。搜索记录支持上一页、下一页和直接选页；刷新或从报告返回时恢复当前页。新页搜索期间可浏览、分析已完成的旧页。历史列表只传页码、时间、状态、条件与岗位数量，选中后再读取当页岗位。再次搜索会在本地排除全部历史页中展示过的标准化链接、跳转后的链接和相同公司/职位/城市的岗位（含修改JD的镜像）；只给模型发送最多48条公开排除链接，完整历史仍由本地核验强制排除。筛选条件变化不重置排除，不同用户或简历互不影响。无新岗位时保留空页并说明，不复用旧岗位凑数；中断页已保存的部分结果仍保留。

快速分 `quick-v1`：已识别技能标签覆盖占70分，岗位方向占30分；已识别学历/年限/届次门槛不满足时最高49分。缺失简历能力按没有处理。未识别的专业资格等仍需审阅。长报告采用独立的细化判断，分数与列表可能不同，不是录用概率。

真实简历只写入独立访客空间，原文与文件保存在本机/部署服务器的SQLite和上传目录；不意味着浏览器离线存储或数据库已加密。请在可信设备上运行、保持回环地址监听；公开部署前需完善账户、存储加密、速率限制和数据清理。不得把密钥放到浏览器代码。`DASHSCOPE_API_KEY`只由后端读取，供应商失败响应不回传原始请求内容。
